## 一、核心判断

根据提交论文和两份演示稿可见的证据，Huang 的工作已经具备与 Yan Ranyudi 演示稿相当的中期研究基础：问题明确、方法已实现、已有结果，并能提出具体的下一步验证。

Huang 的实验覆盖更广，任务输出结构也更复杂；Yan Ranyudi 的核心想法更集中，容易用日常例子解释。不能从系统组件数量、标签数量或 PPT 页数推导创新性更高，也不能凭一个已通过答辩的案例推定本次一定通过。这里的“相当”指材料呈现出的中期研究成熟度，不是对不同研究方向给出统一学术排名。

你的主要风险不是缺少工作量，而是听众能否分清：什么是已有技术、你具体改变了什么、哪些效果已经验证、哪些仍需补实验。

## 三、论文完成度

已具备中期汇报证据的部分

• 问题定义：输入为新闻与指定主体；输出区分主体、细粒度价值和方向；明确 Task 1 与 Task 2 输入边界。
• 研究问题：RQ1 错误诊断、RQ2 数据增强、RQ3 选择性融合，对应后续实验。
• 方法实现：DRA-FEHU、WAIPS-02、WAIPS-03/FGHF 均有流程与实现说明。
• 数据与实验：1,228 篇训练文章、177 篇开发文章、175 篇 Task 1 测试文章；编码器使用三个随机种子；有融合分阶段结果与官方测试分数。
• 定量证据：完整融合的开发集 Micro-F1 从 0.5496 提高到 0.5817；保存输出上的文章级配对 bootstrap 区间为 [0.0209, 0.0433]，仅对应整体差值。
• 负面结果与限制：说明了掩码训练不稳定、方向检查可能引入错误、历史编码器来源不完整、开发集多次用于选择等问题。

仍需验证的关键点

1. 诊断驱动选择是否优于同等规模的一般生成或过采样？目前结果支持“这些生成记录在当前协议下有帮助”，还没有独立证明目标选择策略本身的优势。
2. 增强后的编码器到底给完整融合带来多少收益？重复训练实验与历史 v2 融合分数不是已识别的一一对应关系。需要固定其他输入，比较无编码器、仅官方数据编码器和增强编码器。
3. 门控与方向检查的收益是否稳定？G2/G5 是删除分支的诊断对照，不能当作完整 G4 的所有组件消融；保存输出的 bootstrap 也不等于重新训练/重新调用外部模型后的稳定性。
4. 生成标签质量与阈值选择仍需更系统检查。六条人工检查不足以说明全部生成数据可靠；开发集同时用于多个选择环节。
5. Task 2、主体关联证据、8B 指令模型对照和推理成本分析属于下一阶段，不能展示为已完成成果。

结论：适合作为有实证结果的中期论文；最终学位论文的贡献归因和稳定性验证还没有完成。没有可靠依据把它量化成一个“完成百分比”。

## 四、与 Yan Ranyudi 的同维度比较

维度：任务与工程难度
Huang：多主体新闻、108 个带方向标签、长尾分布、训练与推理两条实验线、跨模型输出对齐和校准。
Yan：将抽象评分标准转为属性、组件、问题清单，再用二元判断聚合分数；还要控制问题冗余、覆盖性与分数尺度。
判断：两者都有实质研究难点。Huang 的输出约束和系统集成负担更大；Yan 的语义标准化与测量有效性不能用组件较少来低估。

维度：想法与创新表达
Huang：诊断驱动的主体—价值—方向样本生成、按训练频次限制预测修订、把标签选择与方向判断分开控制。
Yan：相对需要人工参与的清单构建方法，研究仅由 LLM 完成 rubric-to-checklist 的流程，并探索剪枝。
判断：均主要属于任务方法与流程层面的研究。Yan 的核心差异更容易一句话讲清；Huang 需要突出三个设计背后的共同问题，而不是罗列系统简称。

维度：实验成熟度
Huang：三种子编码器实验、开发集分阶段融合、诊断对照、官方测试、案例分析。
Yan：ELLIPSE 前 100 篇文章的七维度试验，加 Grammar 清单剪枝试验；全数据集扩展仍列为后续工作。
判断：就这两份材料展示的范围而言，Huang 的实验覆盖更充分。但文章数、F1 和相关系数不是可直接比较的质量量尺。

维度：尚未闭合的证据
Huang：缺少等规模增强对照和完整融合中的编码器贡献对照；部分历史记录不完整。
Yan：小样本、评分尺度误差、清单剪枝后质量下降，以及扩大样本的计划。第 20 页文献结果和自身 subset100 结果不能直接视为同模型、同划分的受控比较。
判断：两者均符合“已验证可行性、关键问题仍在研究”的中期状态。不能因为前辈的稿件也有局限，就忽略自己的关键对照。

可用于答辩的创新定位（建议口头表述）
“My contribution is a task-specific way to control value recovery, prediction selection, and direction checking under imbalanced supervision. I evaluate which stages help, where they fail, and which effects still need a matched comparison.”

该表述限定了贡献，不声称新的基础模型、首次提出数据增强，或所有组件均已独立验证。

## 七、外部方法定位核对

EAVIT 的原论文描述了“本地价值检测器先给出估计，再为在线 LLM 构造较短提示”的顺序；Huang 的 FGHF 使用提示系统给出的预测与候选，并用编码器分数辅助修订。这个信息流差异可以说明方法定位，不能代替同条件性能比较。
来源：https://www.ijcai.org/proceedings/2025/934

InteractEval 的作者摘要明确采用人类与 LLM 的 think-aloud 输出生成清单相关属性，支持 Yan 稿件关于其研究设定差异的描述。本文未由此推断 Yan 的新方法已全面优于该工作。
来源：https://arxiv.org/abs/2409.07355

## 八、答辩前最值得准备的回答

1. **你的独立贡献是什么？** 用三个具体改变解释，不把 DeBERTa、LoRA 或一般数据增强说成个人提出的新技术。WAIPS-01 是队友的方案，应清楚区分。
2. **增强为什么帮助最终系统？** 当前证据尚未独立回答。三种子训练与历史融合编码器不是可追溯的一一对应关系，下一步需要固定提示输出进行编码器替换对照。
3. **为什么给少数类增强，却只修订高频标签？** 两个机制作用阶段不同。18 个增强目标均在删除／添加门控之外，不能直接把它们写成已验证的端到端因果链。
4. **提高 3.21 个百分点是否可靠？** 区间对应保存输出上的整体 G4−G0 差值；它不覆盖重训、外部模型重新调用、开发集反复选择或每个组件单独的稳定性。
5. **为什么方向检查有时改错？** 当前标签不能充分区分意图、行为和后果。展示一例修正与一例引入错误，比只展示成功更能说明研究问题。

总体建议：可以把这份稿件作为中期答辩的完整起点。下一次彩排重点检查约 20 分钟内能否自然说完，并练习上述五个问题。最终是否通过仍由导师和答辩委员会依据实际汇报与研究要求判断。

### 暂定完成路径

P22 的八周安排从中期反馈后起算，是待与导师讨论的工作量估计，不是已批准的日期承诺。

- 第 1–2 周：固定主预测与辅助预测，比较无编码器、官方数据编码器、增强编码器。交付匹配协议下的分数差值、区间、检查点与分数文件，回答编码器是否具有独立贡献。
- 第 3–4 周：控制新增数据量，比较针对性生成、一般生成和过采样，每组保留三个种子。交付目标 F1、全空间 Macro-F1 及各次运行记录，回答诊断选择是否优于额外监督本身。
- 第 5–8 周：建立独立选择划分，按生成模式和方向抽样审查标签，重复提示和融合运行，保存审查记录、波动范围与可复现结果包。进一步的主体证据、Task 2 和成本研究在核心比较后安排。

完成标准是获得可解释、可复核的比较，包括没有观察到收益的情况；不以“必须跑出更高分”作为验收标准。

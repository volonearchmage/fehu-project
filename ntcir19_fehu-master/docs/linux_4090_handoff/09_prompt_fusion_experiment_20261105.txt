Task 2：低成本非思考 Prompt 与融合实验
日期：2026-11-05；本文件为运行前协议，真实结果见新实验目录 RESULTS_zh.md。

一、问题与实验单位
本轮回答：关闭思考的 Flash 能否给出有用的 Task 2 判断；三个不同观察方向是否产生可利用的互补错误；融合是否在新的样本上优于原 prompt。
100 条指 100 个子事件，每条覆盖输入给定的全部 actor，绝不是 100 个随意挑出的标签或成功请求。Task2b 的判断单位是 (guid, subevent_id, actor, l1_value, direction)。同一值允许两方向，空集合合法。失败、截断、漏 actor 不能伪装成空预测。

二、模型及费用
请求固定 deepseek-flash、thinking={"type":"disabled"}、temperature=0、JSON output、max_tokens=4096、并发4、单请求超时90秒。不使用 max/high/low，不添加额外反思调用。
DeepSeek 当前文档将 deepseek-flash 和旧 deepseek-v4-flash 指向 DeepSeek-V4.1-Flash-1017；旧名字不是旧权重对照。温度0降低采样随机性，不保证正确、保守或逐位复现。
按当前峰值价 input $0.30/M、output $1.20/M 预算，不依赖缓存折扣。每次调用先持久化保守预留，可靠 usage 返回后结算释放差额；超时/usage缺失保留完整预留，无法确认的在途请求不当成免费请求重发。所有阶段共用预算账本，上限 $1.50，最多360次 HTTP 尝试（336次初始、24次技术重试）。无额外余额查询。
这是按公开价格的程序止损，不是账单保证。所有请求都用满输出上限时所需费用会超过该预算，因此不能保证100条全部完成；到预算边界如实停止，不增加上限、缩小报告分母或换掉失败样本。
新授权仅覆盖此独立实验。旧 task2_prompt_baseline_v1/USER_STOP.json 及历史实验保持不变，旧 full DEV 推理仍不能恢复。
官方控制与价格：https://api-docs.deepseek.com/guides/thinking_mode/ 和 https://api-docs.deepseek.com/quick_start/pricing/ 。记录返回 model、时间、fingerprint、usage 与 reasoning_tokens；缺字段不等于已验证0。

三、三个 Prompt 的职责
A：完整保留旧 frozen system prompt，作为配置比较锚点。全文背景、目标子事件、全部 actor、54个官方值定义、原 JSON schema 不变。
B：主体/子事件归属视角。重点判断该 actor 在目标事件中的具体行为、发言和参与；全文仅用于指代与上下文，不能把别的事件、受害者或其他主体的行为贴给当前 actor。允许隐含价值和合法空集合。
C：行为/价值方向视角。直接对应官方定义判断行为支持了什么、违背了什么；不能把新闻情绪、社会议题、受害事实等同于该 actor 的价值方向。分别判断支持与违背，不强制二选一。
B/C 是不同决策侧重，不是把同一句话换三个说法；仍属于同一模型的相关判断，不能称为三个独立专家。三次输入均不含另外两次的预测或 gold，不要求输出思维链，不要求自报置信度。

四、两阶段样本与冻结顺序
探索阶段：仅在既定 TRAIN fit 中，以输入信息固定选12个不同文章的子事件。排除正文或标题经 collapse-whitespace/casefold 后与 DEV 相同者；不使用 tune/holdout。选择只看输入键，不按 gold、难度或初次结果挑样本。相似报道仍可能漏检，报告此限制。
确认阶段：从完整 DEV 的1526个子事件按预先固定 seed 的 SHA256 排序取100，所有子事件等机会的伪随机选择，不限于旧508成功集合。保留同事件的所有 actor，不为平衡标签而读 gold。保存完整候选总体键、样本键和输入哈希。
在任何 API 调用前冻结输入、三个 prompt、模型参数、融合公式、预算和选择政策。先完成12×3=36条有效结果并评分；选择本轮主要候选、写入 confirmation_lock 后才开始100×3=300条确认推理。确认 gold 仅在所有所需预测完成之后用于评估，不拿确认错误继续改本轮 prompt/gate。
12条只够低成本探索，不能证明已经充分优化。正式确认时报告全部预定候选，但主要结论必须围绕探索阶段选定者与A的比较；若另一个方法事后更好，只能作为下一轮假设，不能偷换主要方法。

五、借鉴 Fusion Gate，但不复制 Task 1 阈值
旧 E7-G4 在 Task 1 用主预测、多 juror、DeBERTa 概率、PAV校准和删除/补充/方向QA。这里先借鉴“有证据才删、补充分开验证”的原则，不声称复现 E7-G4。
对每个 actor-event 的完整有向标签集合 A/B/C，固定以下五个候选：A、B、C、VETO=A∩(B∪C)、CONSENSUS=(A∩B)∪(A∩C)∪(B∩C)。VETO 只删除A中无人支持的标签；CONSENSUS 还允许B/C共同支持的标签补入。方向属于完整 tuple，不能只按价值名投票后任意翻方向。
探索集按官方 Task2b micro-F1 选主要候选；完全同分依次 A、B、C、VETO、CONSENSUS。UNION=A∪B∪C仅诊断候选召回覆盖与误报，不是融合F1上限，也不参与选择。记录 gate 删除/补回的 TP/FP/FN 变化和成员错误重合，不能只报最高总分。
不移植“至少留1标签”“频繁类>130”“每主体最多加2”等 Task1 参数。不在12个事件上拟合108类独立阈值或PAV，不把LLM自报confidence当校准概率。是否值得更复杂 gate，要看互补信息和独立验证的净收益。

六、为什么小样本与 full DEV 可能不同
1. 同文章子事件相关，100个事件不是100篇独立新闻；报告实际文章数，差异区间按文章聚类重采样。该区间是近似稳定性诊断，不是对完整DEV分数的保证。
2. 稀有价值/反向标签可能在小样本缺失；记录有效类别支持数、预测类别、macro-F1的覆盖限制。不能用小样本micro-F1宣布长尾已解决。
3. 输入长度、actor数、子事件位置与每文章事件数影响混淆及成本。输入层面对比样本与full DEV的分布；评估后再描述gold空候选比例和标签分布，不据此换样本。
4. SRS子事件的候选和正标签总量会波动，F1是计数比值，不能把小样本F1当严格无偏的full DEV估计。不能为凑齐每文章覆盖改成不等概率抽样却仍直接用普通micro-F1代表全体。
5. 旧508是非随机成功集合。只对100与旧508交集作历史配对辅助对比，公布交集大小；不能拿新100分数与旧508总分直接相减。历史对比还混有远程模型时间、思考开关、温度和输出上限等差异，不是纯思考强度的因果实验。
6. 官方DEV已有历史开发使用，不是未见最终测试集。即使本轮确认100未用于prompt选择，也不宣称为全新benchmark TEST。

七、如何继续迭代
本轮不因某个小数点结果自动全量付费。先看预定主要候选相对A的净收益、区间、分层表现、错误互补和成本。区间跨0表示证据不充分，不等于确定无效；全部方法都弱则从探索错误提出单一可检验改动。
下一轮 prompt/gate 改动须新版本、新预算、新的分组验证方案；已查看的100条转为开发历史，不能继续叫未见确认。可用 TRAIN fit 更大且按文章分组的开发/校准集进行迭代，再对未参与选择的数据评估。只有有稳定收益才考虑冻结最优单prompt或门控级联跑 full DEV。
full DEV 阶段对每个保留系统完整覆盖同一1526事件，统一官方评分和成本；若使用按分歧触发的第二prompt级联，触发规则仅依赖输入/预测，并在开发集冻结。不能用gold知道“困难”后选择性调用。
full DEV 能检验这份开发数据上的完整效果；迭代一直看DEV会过拟合，最终论文泛化结论仍需未参与开发的合法评估集。没有同集合官方基线原始预测时，不宣称超过组织方或筑波。

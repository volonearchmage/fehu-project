| Method (canonical) | Intended folder | Observed folder | Status |
|---|---|---|---|
| Prompt OAI | `output/task1_prompt/` | `output/task1_prompt/` + `output/task1/` (identical) | OVERLAP |
| Prompt DeepSeek V4 Flash | `output/task1_prompt_deepseek_v4_flash/` | same | OK |

## 2. Overwrite collisions (CRITICAL)

Two scripts share the same default output path:

```
src/run_pipeline.py:54     OUTPUT_DIR = output/task1
src/train_deberta.py:47    OUTPUT_DIR = output/task1
```

Both write `pred_task1a.json` and `pred_task1b.json` directly to `output/task1/` with no model/version in the path. Running one after the other **silently overwrites the other**.

### Forensic evidence (md5 hashes)

| File | md5 | bytes |
|---|---|---|
| `output/task1/pred_task1a.json` | `f7d62ca305f4...` | 83 987 |
| `output/task1/pred_task1b.json` | `abfa93fc28ae...` | 118 508 |
| `output/task1_prompt/pred_task1a.json` | `f7d62ca305f4...` | 83 987 |
| `output/task1_prompt/pred_task1b.json` | `abfa93fc28ae...` | 118 508 |
| `output/task1_deberta/pred_task1a.json` | `16d15bf5c039...` | 149 877 |
| `output/task1_deberta/pred_task1b.json` | `14ee8dba8c73...` | 360 687 |
| `output/task1/pred_task1a_4omini.json` | `65c40a9b4b92...` | 89 980 |
| `output/task1/pred_task1b_4omini.json` | `9ba94060be37...` | 126 044 |

**Conclusions:**
1. `output/task1/` currently contains the **prompt-only OAI** predictions — they are byte-identical to `output/task1_prompt/`. The DeBERTa output that was written to `output/task1/` by `train_deberta.py` no longer exists at that path.
2. `output/task1_deberta/` content differs from `output/task1/` — those are the canonical DeBERTa preds, regenerated via `src/regenerate_deberta_predictions.py`.
3. `output/task1/pred_task1a_4omini.json` and `pred_task1b_4omini.json` are manually-named archives (no script writes these names). They are different content from the unsuffixed files; their model/parameters are not recorded.

## 3. Missing `run_config.json`

Three full-dev result folders lack `run_config.json`:

| Folder | Missing because |
|---|---|
| `output/task1/` | `run_pipeline.py` and `train_deberta.py` do not write run_config |
| `output/task1_prompt/` | Generated by `collect_results.py`, which does not write run_config |
| `output/task1_deberta/` | Generated by `regenerate_deberta_predictions.py`, which does not write run_config |

Consequences:
- Cannot tell from disk whether `output/task1_prompt/` came from `gpt-4o-mini` or `gpt-4o`, or what `cache_dev*.json` it used.
- Cannot tell from disk what DeBERTa checkpoint or threshold produced `output/task1_deberta/`.
- Reproducibility is degraded.

## 4. Cache-folder collisions

| Cache file | Keyed by model? | Risk |
|---|---|---|
| `logs/cache_dev.json` | NO (only by mode) | HIGH — `run_pipeline.py --model gpt-4o-mini` and `--model gpt-4o` would share & overwrite the same cache |
| `logs/cache_dev_deepseek_v4_flash.json` | yes (in path) | LOW |
| `logs/cache_hybrid_dev.json` | NO (only by mode) | MEDIUM — different `--model` args collide |
| `logs/cache_hybrid_v2_dev.json` | NO (orphan, predates fix) | MEDIUM — should be excluded from any new run |
| `logs/cache_hybrid_v2_dev_deepseek_deepseek_v4_pro.json` | yes | LOW |
| `logs/cache_hybrid_v2_dev_deepseek_deepseek_v4_flash.json` | yes | LOW |
| `logs/cache_test_openai.json` | yes (test+openai in name) | LOW |

Additionally `run_pipeline.py` accepts a `--model` argument but **never uses it for API calls** (the `MODEL` constant is hard-coded into `call_gpt`). So the same `cache_dev.json` was used for every run regardless of what `--model` was passed.

## 5. Naming inconsistencies

- `output/task1_hybrid_v2_deepseek_deepseek_v4_pro/`: the literal string `deepseek_deepseek` (provider + slug) is cosmetic but visible. Caused by `OUT_DIR = f"output/task1_hybrid_v2_{provider}_{slug}"` with `slug = model_slug("deepseek-v4-pro") = "deepseek_v4_pro"`. Cosmetic only — not a bug, but worth flagging.
- `output/task1_hybrid_v2/` predates this scheme — orphan.
